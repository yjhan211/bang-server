# BANG Game Server

BANG 게임의 Unity 클라이언트 개발·테스트를 위해 구축한 Node.js·TypeScript 기반 TCP 게임 서버입니다.

2~7명의 플레이어가 방에 모여 각자 부여받은 역할과 캐릭터로 게임을 진행합니다.

플레이어는 캐릭터를 이동하고 공격·방어·회복 등 다양한 카드를 사용하며 역할별 승리 조건을 달성합니다.

서버는 회원가입·로그인부터 방 생성과 입장, 게임 준비·시작, 카드 효과와 캐릭터 상태 갱신, 승리 판정과 종료 통지까지 처리합니다.

이 저장소에는 서버 코드와 클라이언트 통신을 위한 Protocol Buffers 정의가 포함되어 있습니다.

## 기술 스택

Node.js · TypeScript · TCP · Protocol Buffers · MySQL · Drizzle ORM

## 게임 진행

1. **회원가입·로그인**: 클라이언트에서 서버에 접속하고 사용자 세션을 생성합니다.
2. **로비·방 입장**: 방 목록에서 선택하거나 방을 생성하며, 랜덤 입장도 지원합니다.
3. **게임 준비·시작**: 참가 인원에 맞게 역할을 배정하고, 서로 다른 캐릭터와 초기 카드를 지급합니다.
4. **플레이**: 위치 정보를 전달하고 카드 사용·방어 반응·상태 효과를 처리해 참가자에게 결과를 알립니다.
5. **게임 종료**: 역할별 승리 조건을 확인하고 승자 정보를 전송한 뒤 방을 정리합니다.

| 역할          | 목표                                            |
| ------------- | ----------------------------------------------- |
| 타겟·보디가드 | 히트맨과 싸이코패스를 모두 탈락시키기           |
| 히트맨        | 생존한 히트맨이 있는 상태에서 타겟을 탈락시키기 |
| 싸이코패스    | 다른 역할의 플레이어를 모두 탈락시키기          |

참가 인원에 따라 역할별 인원 구성이 달라집니다.

## 서버 처리 범위

- **접속·방 관리**: 회원가입·로그인, 접속 세션, 방 생성·목록 조회·입퇴장
- **게임 상태 관리**: 역할·캐릭터 배정, 위치 갱신, 체력과 캐릭터 상태 전달
- **카드 처리**: 대상 선택, 카드 효과 적용, 반응 요청과 응답 대기 시간 처리
- **게임 종료**: 역할별 승리 조건 판정, 참가자에게 종료 결과 전송
- **통신**: TCP 수신 버퍼에서 헤더와 본문을 읽고, Protocol Buffers 메시지를 해석해 요청별 핸들러로 전달

## 저장소 구성

| 경로              | 역할                                                 |
| ----------------- | ---------------------------------------------------- |
| `src/server.ts`   | TCP 서버 시작 및 연결 이벤트 등록                    |
| `src/events/`     | 연결·수신·종료·오류 처리, 패킷 헤더 해석과 요청 분기 |
| `src/protobuf/`   | 메시지 정의, 생성된 직렬화 코드와 패킷 인코딩·디코딩 |
| `src/users/`      | 회원가입·로그인 요청, 세션과 사용자 데이터 관리      |
| `src/rooms/`      | 방 생성·입퇴장, 참가자 관리와 방 단위 메시지 전송    |
| `src/game/`       | 게임 준비·진행, 위치 갱신과 승리 조건 판정           |
| `src/characters/` | 캐릭터별 동작과 위치·상태 관리                       |
| `src/cards/`      | 카드별 효과, 사용 요청과 반응·타임아웃 처리          |
| `src/db/`         | MySQL 연결, 사용자 스키마와 마이그레이션             |

## 실행 방법

Node.js와 npm이 필요합니다. 저장소 루트에서 의존성을 설치합니다.

```bash
npm ci
```

### 데이터베이스 없이 실행

기본 실행은 `NO_DB=true`를 사용하며, 사용자 데이터를 메모리에 저장합니다. 서버를 종료하면 해당 데이터는 사라집니다.

**Linux·macOS·Windows Git Bash**

```bash
npm start
```

**Windows PowerShell**

```powershell
$env:NO_DB = "true"
npx ts-node src/server.ts
```

기본 접속 주소는 `0.0.0.0:5555`이며, 환경변수 또는 `.env` 파일로 변경할 수 있습니다.

```dotenv
HOST=0.0.0.0
PORT=5555
CLIENT_VERSION=1.0.0
```

클라이언트에서는 서버 PC의 IP와 포트로 연결합니다. Unity 클라이언트는 이 저장소에 포함되어 있지 않습니다.

### MySQL 사용

로컬 MySQL에 사용할 데이터베이스를 생성하고 `.env`에 연결 정보를 설정합니다.

```dotenv
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=your_user
DB_PASSWORD=your_password
DB_DATABASE=your_database
```

`NO_DB` 환경변수를 해제한 상태에서 다음 명령을 실행합니다.

```bash
npm run migrate
npm run dev
```

현재 서버의 DB 연결 코드는 `DB_USER`, `DB_PASSWORD`, `DB_DATABASE`를 사용하며 호스트·포트는 MySQL 드라이버 기본값을 사용합니다. `DB_HOST`와 `DB_PORT`는 마이그레이션 설정에서 사용합니다.
